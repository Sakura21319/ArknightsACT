## 本轮结果

- 保留每阶段 2×2 的住宅、商业、工业、检查站布局，每区从 30×24 调整到 **36×30**，总面积增加 50%；地面、边界、底盘与道路继续共用 WorldMetrics。
- 生产地图的近景房屋均有可进入空间。两座住宅立面、两间商铺、工业厂房、检查站门房从实心体改成分段墙体、门洞、地板与室内物资箱。原有住宅、商业房间、检查棚、双层设施继续使用，共计 **10 处空间**。地图边界外的天际线是不可达远景，不属于探索房屋。
- 入口有住宅门洞、商业宽敞店面、工业装卸门，以及原有外置坡道。住宅坡道移到侧面，新增二层平台，并修正导航节点，避免原坡道压在一层门口。关闭了原先遮住门洞的装饰门板。
- `EnterableBuilding25D` 提供真实室内范围与无碰撞屋顶的遮挡检测；正交相机使用平行视线。屋顶和墙体变为 20% 透明，碰撞保留，室内地板与搜索箱保持实体可见。
- 房屋导航在密度清理结束后追加入口路线，外部连接使用角色宽度的碰撞探测。仍使用现有 PrototypeNavigationGraph25D，不引入另一套导航生成器。
- 道路增加暗色颗粒沥青、哑光旧漆标线、人行道接缝、修补块、排水格栅。建筑增加门框色带和街区编号。默认白色管桥/塔柱替换成环境套件材质，移到可玩区外，跟随 StageRoot 重建；2×2 生产地图停用重复的旧白色中心十字标线。

## 搜索与撤离

每阶段固定 **9 个搜索容器**：六座改造房屋各一个，原有住宅与商铺各一个，双层工业设施一个。旧普通/尖刺/怪物宝箱系统继续存在。

操作：

| 操作 | 行为 |
| --- | --- |
| 接近容器并按住 F | 2.6 秒搜索；必须在 2 单位范围内且视线无遮挡 |
| 移动、松开 F、受击、暂停、离开范围 | 搜索进度重置；箱盖逐渐关闭 |
| 搜索完成 | 箱盖完全打开，藏品进入 4 格未结算背包；每箱只能领取一次 |
| B / 藏品目录按钮 | 查看 22 件藏品、ACT 适配描述、当前职业适用性与本局已入库数量 |
| 前两阶段击败 Boss 后在出口按 E | 藏品结算到现有 CollectibleInventory，再进入下一阶段 |
| 最终 Boss 胜利 | 自动结算本阶段藏品，结束继续搜索 |
| 阵亡 | 未结算藏品丢失；已结算藏品不由搜索系统扣除 |

搜索表现是程序化动画：**解除封装 → 箱体扫描 → 藏品识别**，包含铰链箱盖、移动扫描条、百分比、稀有度色条、未知物品到名称的揭示。界面采用深色战术信息面板、薄荷绿扫描色与方舟工业标识。当前每箱一件，不是多物品排列背包，也没有新增陈的 Spine 翻找骨骼动画。

满包或叠加上限时不会消耗容器。掉落在创建时得到独立 seed，不消耗战斗随机流，阶段名称参与 seed。所有职业的物品都会出现，当前可用效果的权重乘 2.3，减少现阶段陈频繁拿到不可用物品的挫败感。原稀有度权重为普通 1、稀有 0.5、史诗 0.2。

**边界：目前是本局阶段之间的搜集和撤离结算，不包含跨游戏存档仓库、交易市场、提前结束本局的撤离点或装备掉落。** “预留效果”只收藏、计数，不宣称已对当前战斗生效。

## 藏品数据与扩展接口

数据入口：`Assets/_Game/Resources/ScavengingCatalog.json`，包含 22 件真实方舟藏品名称；全部数值和效果说明是本项目 ACT 适配，不照搬塔防数值。

名称核对来源：[PRTS 水月与深蓝之树收藏品图鉴](https://prts.wiki/w/水月与深蓝之树/生物制品陈设)。不使用或复制其图标、美术和叙事文案；箱体是现有环境材质与倒角网格生成的原创占位资产。

| 方向 | 当前目录 |
| --- | --- |
| 近卫 | 折戟-突破、折戟-锋刃、折戟-浴血 |
| 通用 | 难闻的止血剂、石像鬼塑像、热水壶、特殊抑制器 |
| 狙击 | 显圣吊坠、银餐叉、损坏的左轮弹巢、残弩-神速 |
| 术师 | 断杖-突破、断杖-织法者、断杖-凝神 |
| 辅助 | 支柱-勤奋、支柱-援护 |
| 医疗 | 医者-突破、医者-妙手 |
| 特种 | 锈刃-可视静谧、锈刃-神力 |
| 先锋 / 重装 | 积攒之手、《旧高卢地名源流考》 |

扩展步骤：

1. 新物品添加 JSON 条目：唯一 `id`、名称、描述、`effect`、`profession`、`rarity`、`value`、`stacks`。使用现有效果无需改搜索系统。
2. 新角色在 `PlayerCombatProfile.SetProfession()` 声明职业，同时配置原有 CombatFeature。陈工厂已设置 Guard；旧场景只对带 ChenSkill1 的角色补迁移，其他角色不会默认变成近卫。
3. 新效果枚举只能追加，不能更改原来枚举的序号。已有伤害、生命、命中回技、施法回血与施法回技可直接用。
4. 新角色系统实现 `ICollectibleEffectConsumer.SupportsCollectibleEffect()`，用 `CollectibleInventory.GetEffectTotal(type)` 读取已结算且适用当前职业的总量；需要立即刷新时订阅 `Collected`。注册接口只是表示消费者已实现能力，真正的行为由该角色系统消费数值。
5. 新增的攻速、护盾、治疗强度、召唤伤害、再部署、推拉、击杀资源和光环类型是预留协议。没有消费者时 UI 标为预留。不要仅删掉“预留”字样就视为已实现。

关键文件：

- `World/RogueliteStagePlayableArchitectureController.cs`：统一房间外壳与真实碰撞；CityStreets 委托它生成。
- `World/EnterableBuilding25D.cs`、`World/RogueliteStageActorOcclusionController.cs`：室内范围与透视。
- `Treasure/SearchableContainer25D.cs`：容器注册、独立 seed、箱体与动画。
- `Treasure/ScavengingInventory25D.cs`：输入、范围/视线、搜索状态、背包、结算、界面。
- `Treasure/ScavengingCatalog.cs`：数据加载与 ID 校验。
- `Collectibles/CollectibleInventory.cs`：职业适用性与统一效果消费入口。

以上相对路径均基于 `Assets/_Game/Scripts/Gameplay/Roguelite/`。

## 验证与复现

使用项目指定的 **Unity 6000.0.23f1** 打开现有 `PrototypeRun.unity`，无需重新生成整个场景即可加载本轮运行时代码。不要用 6000.6 自动升级场景。

批处理入口 `ArknightsACT.Editor.CityExplorationValidation.Run` 会打开现有场景进入 Play Mode，并完成三阶段检查，不保存或重建生产场景。测试会主动换阶段、瞬移与模拟搜索，不能当成手动完整通关记录。

本轮验证：Unity 脚本编译；Stage 1→2→3 实际生成；每阶段 10 个空间/9 个容器；角色宽度门洞探测；新房屋导航连通；搜索移动中断、暂停不推进、满包不消耗、重复搜索不复制、结算只发一次、死亡仅丢未结算物品；无运行时 Error/Exception。结果和截图在 `Logs/CityExploration/`，日志在 `Logs/CityExplorationValidation.log`。

场景渲染截图已检查建筑外观、道路、室内陈可见性。批处理环境没有输出 OnGUI 的 ScreenCapture 图，因此搜索 HUD 的不同分辨率、键鼠手感及箱盖动画整体观感仍建议在交互式编辑器中复核。自动导航连通检查也不替代真实敌人的长时间追击与上下楼压力测试。

## 后续玩法建议（未在本轮实装）

1. **可选提前撤离**：起点设置一次性撤离终端，读条 6 秒；低风险离开与继续争取 Boss 奖励形成选择。优先完成本局胜负/结算状态后再接跨局仓库。
2. **按容器给线索**：居民箱偏生存、商铺偏经济、工业箱偏技能、门房偏稀有。尽量让建筑功能能预测奖励方向。
3. **声音带来局部风险**：高级密封箱搜索更久，开启时吸引附近巡逻，不必直接增加全图敌人数。
4. **无用藏品仍有价值**：后续商店支持兑换一小笔源石锭或委托材料；避免在只有陈可选时让异职业物品永远占用成长机会。
5. **先做委托再做重量系统**：如“带出一件工业档案”，以清楚的路线目标丰富探索；暂不引入复杂重量、弹药和维修成本。
