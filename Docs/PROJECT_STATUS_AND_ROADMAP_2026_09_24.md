## 项目定位

项目当前方向是 **2.5D ACT 战斗 + 切尔诺伯格连续城区探索 + 搜打撤循环 + 轻度肉鸽构筑**。当前目标是把已有原型的整局流程、战斗、角色表现和稳定性验收完成，再深化局外成长；此阶段不扩展新城市、完整编队或多人联机。

## 验收状态与边界

- 项目构建设置将 `PrototypeRun.unity` 设为启用场景，根目录 README 提供了场景生成入口和当前操作说明。
- 之前的开发记录报告过城区生成与几何校验、源码级编译 / 校验；本次没有重跑这些检查，因此不把它们当作当前验收结果，也不能替代正式 Unity 场景中的完整 Play Mode 验收。
- 仓库包含 11 个 EditMode 测试脚本。本次整理只检查文档和源码，没有启动 Unity，也没有运行测试，因此不把当前编译或测试标记为已通过。
- 仍需实机确认：完整搜打撤闭环、角色切换后的运行时一致性、角色动画与技能、UI 分辨率、正式场景性能、长时间运行和新局重置。
- 当前没有真正的多人联机实现。设施上的 Authority / Revision 等字段只为将来扩展预留。
- 工作区存在 FrostNova Spine Atlas / Material 的未提交变更；此进度总结不把这些资源变更视作已完成验证。

## 后续计划

### P0：完成可玩原型验收

1. 在 Unity 6000.0.23f1 打开项目，先处理 Console 编译错误，再运行现有 EditMode 测试。
2. 在正式场景走通主页 → 行动准备 → Stage 1 搜索与战斗 → Stage 2 / 3 推进或返程 → 撤离 → 结算 → 仓库交易 → 第二局。
3. 覆盖背包拖拽 / 整理 / 丢弃 / 重拾、藏品生效、城市设施、地图导航、登高路线、跨 Stage 物品风险和死亡丢失规则。
4. 集中收尾 FrostNova 与 Schwarz：动作映射、技能特效、皮肤切换、正式 SP / 冷却和调试状态恢复。
5. 检查 HUD / 小地图遮挡、键位冲突、16:9 与 4K 布局、角色切换和场景帧率；修复验收中发现的问题。

### P1：正式化战斗数据与表现

当前代码实现已推进到第一版正式化：

- 玩家、普通敌人与 Heavy/Boss fallback 已配置当前 ACT 数值尺度下的 DEF / RES；Boss 已通过 `StatusResistanceProfile` 配置硬控缩短、移动受限缩短与缴械免疫。
- 技能生命周期新增统一的 Detached / Permanent / Duration / Ammo 四类适配；Active 技能不会继续回复 SP，永久/持续/弹药状态不会被再次按键当作取消。
- Schwarz S2/S3 已迁移为 Duration 并退出无限持续调试；FrostNova 两个技能已退出 1/1 无限技力并恢复正式 SP 消耗/回复。
- FrostNova 冰系技能已接入 `Cold -> Freeze` Status 反应链；正式 HUD 已能显示技能生命周期状态和当前异常状态/剩余时间。
- 仍需 Unity 真编译与 Play Mode 验证物理、法术、真实伤害、穿透、减防、Aura、控制中断、DOT、四类技能生命周期，以及补最终冰冻/燃烧/缴械图标和世界表现。

## 不应回退的规则

- 真实撤离才会把普通物资转入长期仓库；跨 Stage 不代表安全结算。
- 藏品只在当前 Run 生效，源石锭是 Run 资源，龙门币是长期货币。
- 118 件藏品 / 收集品以 `Docs/RogueRelics/RogueRelicDatabase_IS1_CurrentPool.xlsx` 为人工维护源；改表后通过 Runtime Importer 同步，不手改运行时 JSON。
- 通用 Gameplay 不按角色名分支；角色专属逻辑留在角色层，角色表现不负责真实伤害结算。
- 局内角色切换统一走 `PlayableOperatorSwitchController`；普通城区房屋维持规则排列，不恢复整片随机错位。
- 当前项目没有正式网络同步；本地 Authority 标记不构成服务器校验。
