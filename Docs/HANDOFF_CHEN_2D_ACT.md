# Handoff — Ch'en 2D ACT Prototype

> This document is the current source of truth for the gameplay prototype on branch `feat/phase-03-spine-presentation`.
>
> Read this before changing player combat, PRTS presentation, controls, or prototype-scene composition.

## 1. Product direction

The project has returned to a **horizontal 2D ACT Roguelite** direction.

Current playable main character: **Ch'en / 陈**.

The previous Texas, Survivor and TopDown experiments were prototypes only and have been removed from the active code path. Do not reintroduce them unless the user explicitly requests a new experiment.

The immediate goal is not to build the full Roguelite layer. The immediate goal is:

```text
make Ch'en's authored PRTS actions feel good as a small horizontal ACT moveset
```

Validate the base combat first; only then rebuild character-specific Roguelite upgrades.

## 2. Explicit user decisions — do not override

Current moveset constraints:

- Ground basic attack: **3-hit combo**.
- **No air attack**.
- **No plunge/downward attack**.
- **No Dash Attack / post-dash attack**.
- Dash remains movement / invulnerability / attack-cancel utility only.
- Two active skills are allowed.
- No auto attack.
- Remove generated/basic-attack slash VFX and procedural sword effects.
- Keep minimal hit feedback: hit tint/flash, HitStop, small camera shake, knockback.
- Do not build around support/co-op operators at this stage.
- Keep code responsibilities separated; do not grow a giant player controller.

## 4. Current move-to-animation mapping

This mapping is intentional and is based on the real authored action library.

```text
Basic 1 -> Attack, normalized 0.00 .. 0.50
Basic 2 -> Attack, normalized 0.50 .. 1.00
Basic 3 -> Skill

Skill 1 -> Skill_2, then Skill_End_2
Skill 2 -> Skill_3, then Skill_End_3

Idle  -> Idle
Death -> Die
Move  -> build_char_010_chen Move retargeted onto combat skeleton
```

`Attack_Pre`, `Attack_End` and `Skill_End` are currently not independent gameplay actions.

Current presentation playback speeds in `ChenPresentationDriver2D`:

```text
Attack halves : 2.00x
Basic 3 Skill : 1.80x
Skill 1       : 1.50x
Skill 2       : 1.55x
```

Do not add procedural bone animation merely to create more attacks. If the authored split feels wrong, first tune the split point / playback speed / gameplay timing.

## 5. Controls

Desktop prototype:

```text
A / D             Move
Space             Jump
J / Left Mouse    3-hit basic combo
K / Left Shift    Dash
L                 Skill 1 — 赤霄·拔刀
I / Right Mouse   Skill 2 — 赤霄·绝影
```

Current rules:

- Basic attacks are ground-only.
- Skills are ground-only.
- Pressing attack during an active Dash does nothing.
- Dash can cancel an attack only after that attack's configured cancel point.
- Cancelling an attack resets the combo to Basic 1.
- Starting a skill cancels the current basic attack and resets the combo.
- Skills cannot start during Dash or while another skill is casting.

## 13. Hit feedback vs attack VFX

The user asked to remove attack effects. Interpret this as:

### Removed / avoid

- generated slash trails
- sword-wave sprites
- procedural decorative attack arcs
- effects that visually replace the authored sword animation

### Keep

- `DamageTintFlash2D` / enemy hit flash
- HitStop
- small Camera Shake
- gameplay knockback

These are combat feedback, not authored attack VFX.

## 14. Architecture rules

Maintain these boundaries:

- Do not create a giant `PlayerController`.
- Do not put Ch'en-only skill rules into `PlayerAttackController`.
- Do not let animation directly modify HP.
- Do not hardcode PRTS asset paths inside Gameplay / Combat.
- Do not make the hidden BaseMotion skeleton become the visible combat character.
- Prefer composition over inheritance.
- Gameplay owns damage; Presentation consumes gameplay events/state.
